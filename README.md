# merge_excel.py — 把一个目录里的 Excel/CSV 合成一张表

给谁用：每月要手工把十几个分店 / 分公司 / 分月报表复制粘贴到一起的行政、运营、电商。

一件事：把一堆结构相同的表，合成一张，自动加一列「来源文件」标明每行来自哪个文件。

## 安装

```bash
pip install openpyxl
```

只要这一个依赖，Python 3.8+ 都能跑。

## 用法

```bash
python merge_excel.py <目录> [-o 输出.xlsx] [--sheet 工作表名] [--keep-header] [--raw]
```

| 参数 | 说明 |
|---|---|
| `-o` | 输出文件名，默认写到 `<目录>/合并结果.xlsx` |
| `--sheet` | 指定读哪个工作表，默认读第一个 |
| `--keep-header` | 每个文件都保留表头（默认只留第一份文件的表头） |
| `--raw` | CSV 不做数值识别，全部按文本写入 |

## 实际跑出来的样子

输入 3 个文件（2 个 xlsx + 1 个 csv），其中 CSV 里有千分位金额和前导零编码：

```
$ python merge_excel.py ./报表 -o 合并结果.xlsx
输出: ./报表/合并结果.xlsx
合并 2 个文件，共 4 行数据
   杭州店.xlsx                         1 行
   边界测试.csv                         3 行
```

输出内容（括号里是写入 Excel 的真实类型）：

```
('订单号','str')  ('日期','date')   ('销量','int') ('金额','int') ('备注','str')        ('来源文件','str')
(2001,'str')      (2026-08-05)      (9)            (900)          ('xlsx来源')          ('杭州店.xlsx')
(1001)            (2026-08-01)      (12)           (1200)         ('正常')              ('边界测试.csv')
(1002)            (2026-08-02)      (7)            (1500)         ('含逗号千分位')      ('边界测试.csv')
('007','str')     (2026-08-03)      (3)            (300)          ('前导零编码')        ('边界测试.csv')
```

## 它处理掉的三个真实坑

CSV 读进来一律是字符串。直接写进 Excel，数字列会变成文本 —— 看着像数字，求和却是 0。这个工具做了三件事：

1. **数字还原**：`1200` 写成数字 1200，不是文本 `"1200"`；千分位 `"1,500"` 还原成 1500。
2. **日期还原**：`2026-08-01` 写成真日期，可以直接做透视表。
3. **不擅自改你的数据**：像 `007` 这种前导零编码（工号、门店号、部门码）**保留为文本**，不会被改成 7。含逗号但不是千分位的字符串也原样保留。

拿不准的一律当文本，不猜。想全部按文本写就加 `--raw`。

## 已知限制（先看这个，别踩坑）

- **不支持旧版 `.xls`**（Excel 97-2003）。只支持 `.xlsx` 和 `.csv`。遇到 `.xls` 会打印「跳过」并继续，不会中断，也不会静默丢数据。
- **假设各文件列结构一致**（列的顺序和含义相同）。列名不同、顺序不同的表（比如不同银行的账单），合并前需要先把列名对齐，这个工具不做自动对齐。
- **只读每个文件的第一个工作表**（或用 `--sheet` 指定一个）。多工作表合并暂不支持。
- 公式单元格读的是**计算结果**（`data_only=True`）。文件从没被 Excel 打开过、没有缓存结果时会读到空。

## 为什么是命令行

因为这活的典型场景是「文件夹里躺着 30 个门店报表，每月来一次」。命令行一条语句跑完，不用每次开网页、不用上传文件到任何服务器 —— 数据不出本机。
